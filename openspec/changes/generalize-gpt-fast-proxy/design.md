# Design

## Context

动机见 [提案](<openspec/changes/generalize-gpt-fast-proxy/proposal.md>)；行为契约见 [本次增量规格](<openspec/changes/generalize-gpt-fast-proxy/specs/tokenhub-fast-tier/spec.md>)。

已读现有宿主、客户端、包清单、bundle、测试和 README，采用以下事实作为基线：

- [宿主 Config](<lib/index.js#L29-L36>) 只有 `enabled` 和 `models`，默认开启；`fast` 与 TokenHub 地址是常量，环境变量只用于测试覆盖。
- [请求处理](<lib/index.js#L89-L106>) 用路径前缀判断 Responses，并在请求体接收结束时读配置。新版需要精确接口判断，并把快照时间提前到请求开始。
- [转发函数](<lib/index.js#L119-L151>) 使用 `new URL(req.url, base)`，以 `/` 开头的本机路径会替换上游路径，不能直接支持带前缀的 API baseURL。
- [代理测试](<test/proxy.test.js#L167-L184>) 当前明确允许路径穿越规范化后访问 `/evil`。新版保留 API 前缀，因此必须把这个预期改为拒绝，不是只增加 URL 输入框。
- [客户端表单](<lib/client.js#L71-L127>) 已使用 Host 的 `form.state` / `form.mutate(ops, revision)`；开关即时提交、模型列表有草稿。恢复默认目前只 unset 两个字段。
- 当前 `node:test` 用本地 HTTP stub、随机测试端口，覆盖 20 个用例。沿用它们，不新增代理框架或测试框架。

设计跨越包标识、宿主与客户端，且改变认证目标校验、配置快照和 URL 映射，因此需要此设计文档。既有规格路径 `tokenhub-fast-tier` 继续使用；插件改名不等于能力目录必须改名。当前阶段不修改主规格及旧归档。

## Goals / Non-Goals

**Goals:**

- 在既有 HTTP 代理中增加单一可配置出口，保持 DSH 适配器、协议处理和流式消费不变。
- 将目标 URL 校验、路径映射和配置快照放在共用请求路径，避免两个生成接口各自实现转发逻辑。
- 让 GUI 草稿、已提交配置和实际请求行为一致，错误时不部分写入。

**Non-Goals:**

- 多中转站、端口配置、模型自动发现、模型类型识别、逐模型档位和协议转换。
- 旧包名别名、旧 ID 配置导入、自动迁移或工作区目录改名。
- 额外密钥存储、自实现 LLM 适配器、修改提供商配置、WebSocket、测速或计费验证。

## Decisions

### D1：继续使用原生进程内代理，同步全部标识

沿用 `node:http` / `node:https`、同步 `ctx.effect`、固定 8788 和 response pipe。只扩展现有宿主和客户端，保留包结构与依赖。

包清单、锁文件根记录、宿主 `name`、bundle row 的 `id` / `name`、浏览器模块 `id` 都使用 `dsh-tokenhub-gptfast`。客户端配置绑定键为 `dsh-tokenhub-gptfast#dsh-tokenhub-gptfast`，本地化、日志和界面文案同步更新。旧标识不得残留在活动代码、安装元数据或现行安装说明中；历史归档和历史说明不做机械替换。

不注册新的模型路由或自实现协议适配器：现有代理已能保留 DSH 的模型、认证和协议行为。也不做旧名称兼容层：用户已明确旧版未正式发布，直接重新安装。

### D2：四项 volatile 配置，正式出口只来自配置

| 字段 | 类型 | 默认 | 提交方式 |
|---|---|---|---|
| `enabled` | boolean | `false` | 开关即时提交 |
| `upstreamBaseURL` | string | `''` | 保存 |
| `models` | string[] | `['gpt-6-sol', 'gpt-6.1-sol']` | 保存 |
| `tier` | `fast` / `priority` | `fast` | 保存 |

四项都标为 volatile，沿用现有 accessor `.get()` 与 Host 表单，不添加自建设置 Service。删除生产中的 TokenHub 默认出口和旧环境变量兜底；本地测试也明确传入配置，不能凭开关关闭就隐式获得旧上游。

只精确比较请求体里的模型 ID 与 `models`；不增加 GPT 正则或模型目录查询。白名单由用户承担选择责任，默认两个 ID 是面向首批同事的预设，不是通用模型识别规则。

### D3：共享 URL 校验和 API 根路径映射

使用标准 `URL`，在界面保存前校验，并在宿主使用配置前再次校验。宿主是发送凭据前的最终边界，不能只依赖浏览器校验。

具体规则：允许绝对 HTTPS URL；HTTP 仅允许规范化的回环地址，如 `127.0.0.1`、`localhost`、`[::1]`，用于本地 stub。拒绝用户名、密码、查询串、片段、非 HTTP(S)、代理自身的回环 8788，以及以生成接口完整路径结尾的地址。允许初始空配置存在，但点击保存时地址必填。记录这些作为明确的实现细节：API 根路径不携带查询参数，业务查询参数来自请求；不自动猜测或补 `/v1`。

API baseURL 的末尾统一为一个分隔符。本机 `/v1/` 是代理挂载前缀，不是必须复制给上游的版本号：去掉该前缀后，把接口相对路径追加到上游 API 根路径，再保留请求查询串。不能将本机绝对路径直接交给 `new URL(req.url, base)`。

| 配置的 API baseURL | 本机请求 | 上游目标 |
|---|---|---|
| `https://relay.example/v1` | `/v1/responses` | `https://relay.example/v1/responses` |
| `https://relay.example/v1/` | `/v1/chat/completions` | `https://relay.example/v1/chat/completions` |
| `https://relay.example/gateway/openai/v1` | `/v1/responses?trace=1` | `https://relay.example/gateway/openai/v1/responses?trace=1` |
| `https://relay.example/openai` | `/v1/models` | `https://relay.example/openai/models` |

解析并验证本机路径与规范化后的目标路径；拒绝绝对请求行、协议相对地址、绕过本机前缀或越出上游 API 根路径的穿越。连接主机与 Host 都固定来自已验证配置，不能来自请求内容。只识别 `/v1/responses` 与 `/v1/chat/completions` 的完整 pathname；查询串不影响接口命中，子路径不注入。

相比允许任意目标或自动拼 `/v1`，这套映射更接近用户填写的 API baseURL 含义，同时避免将认证头发到错误路径。

### D4：请求开始时读取一次完整快照

在 HTTP request 回调开始时读取四个 accessor，复制模型集合，验证并规范化目标。后续接收 body、注入、转发和响应都使用这个快照，不再读取实时配置。此时即可保证请求体上传中或 SSE 返回中的请求都不切换站点、档位或白名单。

保持 `injectTier` 为可独立测试的 JSON 处理函数，只增加所选档位参数；两个接口共用它和 `forward`，不要复制判断与转发分支。已有字段、非对象和白名单未命中时返回原 Buffer。

未配置或无效上游、异常配置档位：本地返回 503 JSON 配置错误，不连接任何默认上游；禁止路径：返回 404；上游连接失败：保留 502 的边界。错误信息不回显原始凭据、请求体或带秘密的无效 URL。状态码是本设计固定的实现细节，不新增配置项。

### D5：原生表单、一个保存动作和局部恢复默认

在现有配置 cell 中增加有标签的 URL 输入和原生 `select`，继续用现有主题 token 和中英文文案，不增加组件库。提示 API 地址的含义、本机代理地址，以及认证头会被发送给所填目标。

地址、模型和档位使用本地草稿，保存时用一次 `form.mutate` 提交三个字段，并携带最新表单 revision。开关只提交自己的字段，不捎带保存其它草稿。校验或提交失败时显示错误并保留草稿，不显示成功；重复操作期间避免并发重复提交。

恢复默认仅 unset `enabled`、`models`、`tier`，绝不 unset `upstreamBaseURL` 或整个 `config`。成功后清除相应旧草稿，使表单显示默认关闭、两个默认模型和 `fast`；地址显示已保存的原地址。未保存地址草稿不会被恢复默认暗中提交。控件均有可访问名称，错误反馈能被辅助技术读取。

### D6：验收请求行为，不宣称实际上游加速

既有认证头、Content-Length、固定 Host、identity encoding 和 SSE pipe 保持。上游错误、普通档回显与重定向直接透传，不添加重试、降档或重定向跟随器；DSH 自身的行为不由插件改写。

扩展原有 `node:test`，使用本地 stub 验证两个接口、两个档位、别名、精确路径、目标前缀、配置快照、URL 拒绝、无默认出口和错误透传。界面保存、局部恢复和绑定在另获授权的安装验证阶段检查。真实测速与收费不属于验收前提，旧测速仅能作为有条件的历史观察。

## Risks / Trade-offs

- [中转站接受不同档位或不透传字段] → 用户选 `fast` / `priority`，原错误透传；不假装通用插件能保证实际选档。
- [地址填错会改变认证头的接收方] → 明确目标提示、HTTPS 约束、宿主校验、禁止自动重定向；不记录秘密。
- [域名可由 DNS 映射到本机或内网] → 静态 URL 校验拒绝已知回环自身写法；不引入 DNS 钉住或任意站点探测。用户必须信任所配置的域名，不能承诺静态检查能发现所有 DNS 别名或重绑定。
- [代理是原提供商整条路由的单点] → 配置好上游后才改 DSH 地址；端口占用只警告不代表路由可用；回滚先恢复直连地址。
- [旧默认和旧测试假设与新行为冲突] → 更新默认开启、环境变量出口、前缀注入与允许路径穿越的测试；保留其它已成立的认证、字节与流式检查。
- [当前旧版已占用 8788] → 不在提案阶段动它。安装前核实端口归属，先经用户授权完成旧实例停用与卸载；不杀未知进程、不并装新旧版本。

## Migration Plan

不迁移配置，不保留旧 ID 兼容；以下是重新安装与启用顺序，不是自动迁移：

1. 实现完成并通过本地测试、语法和 manifest 检查；当前规划不执行这些代码改动。
2. 安装验证前另行取得授权，确认当前 profile、8788 监听者和需要测试的提供商。若提供商已指向旧代理，用户先恢复其原直连地址，再卸载旧 bundle；不得自动复制旧插件配置。
3. 安装新版，按管理工具的 `application` 结果决定是否需要重启，不凭源文件修改承诺 HMR 或热安装成功。
4. 通过新版 GUI 手动填写目标 API baseURL，默认模型可保持，按需选档并保存；随后用户把原提供商 API 地址改为 `http://127.0.0.1:8788/v1`，需要时开启 Fast 请求。
5. 验证字段注入、开关透传、保存热生效与局部重置。采用测试提供商或本地 stub，恢复测试改动；不改共享凭据，不以吞吐或响应档位作为 Fast 已生效的证明。
6. 回滚时先把提供商恢复直连，再卸载新版；关闭配置开关只是不注入，不能替代卸载前恢复直连。

## Open Questions

没有阻塞设计的未确认需求。实际安装验证的 profile、时机及端口释放操作留待用户授权；它们不改变本次契约和任务分解。
